## 一、项目概述

### 1.1 项目定义

**"归零"数字遗产管理系统**：一款面向普通公民的全生命周期数字遗产规划工具。帮助生前用户**发现、登记、处置规划**自己所有数字资产，在不幸离世后帮助继承人**有序、合规地继承**所有数字遗产。

### 1.2 一句话定位

> **"你的数字人生，值得一个有归处的终点。"**

### 1.3 项目名称

- **中文名**：归零（双关："归"=回归归属，"零"=归零处理/清空）
- **英文名**：DigiLegacy / NextOfKin
- **Slogan**：数字有数，归处有路

### 2.2 需求痛点（三层）

#### 第一层：个人痛点（生前用户）

- **不知道自己有多少数字资产**：手机号绑了哪些平台？注册了哪些APP？开了哪些会员？根本记不全
- **不知道密码给了谁也没用**：就算告诉子女密码，平台用格式条款拒绝配合过户
- **不知道数字遗产的法律属性**：微信余额能继承吗？游戏账号里的装备算不算遗产？聊天记录能不能看？
- **想立遗嘱不知道怎么写数字部分**：传统遗嘱库对数字遗产的覆盖有限

#### 第二层：继承人痛点（身后家属）

- **"死亡循环"**：平台要求法院判决书才给查→法院要求先知道账户里有啥才能判决→不查就不知道→无法判决
- **信息黑箱**：不知道逝者有多少账号、里面有多少钱、绑了哪些银行卡
- **流程黑洞**：每个平台继承手续不同，没有统一指引，跑断腿
- **情感创伤**：父母想找回子女的聊天记录、照片留念，但账号已被平台注销

#### 第三层：社会/治理痛点

- **数字资产沉睡**：大量资金、有价值账号因无人继承而永久冻结在平台
- **家庭纠纷**：数字遗产分配不透明导致继承纠纷
- **法律空白**：《民法典》第127条对虚拟财产仅原则性规定，缺乏操作细则
- **平台孤岛**：各平台缺乏统一的数字遗产处理接口

### 2.3 政策窗口（重大利好）

| 时间 | 政策/事件 | 意义 |
|------|-----------|------|
| 2021.01 | 《民法典》施行，第127条原则保护虚拟财产 | 法律底层已打通 |
| 2025.10 | 浙江试点"个人身后金融事"一站式查询 | 政府开始着手解决 |

| 2025 | 中华遗嘱库发布《白皮书》明确数字遗产成新趋势 | 权威机构背书 |

### 3.2 蓝海确认

**结论：目前市场无任何产品覆盖"数字资产发现→分类登记→处置规划→法律文书生成→身后执行→继承人向导"的全链条。**

我们的独特定位：
1. **唯一覆盖中国本土全平台**（100+平台数据库）
2. **唯一主动发现型**（不只是被动记录，而是帮用户"想起"可能遗忘的资产）
3. **唯一法律+技术双引擎**（不只解决"密码给谁"，更解决"法律上怎么继承"）
4. **唯一继承人友好型**（不只面向生前用户，也面向继承人提供操作向导）

### 4.2 六大核心模块

#### 模块一：数字资产发现引擎（核心壁垒）

**功能描述**：帮助用户查清自己拥有的所有可能数字资产。

**核心机制**：
1. **手机号交叉推断**：用户输入手机号，系统根据号段及注册域名特征，匹配可能注册的平台
2. **身份证号辅助推断**（可选，经用户授权）
3. **平台数据库扫描**：内置自建的中国数字资产平台数据库（100+平台），逐一给出"有无账号"概率提示
4. **用户主动勾选确认**：最终由用户在清单上勾选确认

**内置数据库分类**（部分示例）：

| 类别 | 包含平台 |
|------|----------|
| 支付金融 | 支付宝、微信支付、云闪付、京东支付、美团支付 |
| 社交通讯 | 微信、QQ、微博、小红书、抖音、快手、B站、知乎 |
| 游戏 | 腾讯游戏全系、网易游戏、Steam、Switch Online |
| 电商 | 淘宝、京东、拼多多、唯品会、闲鱼、得物 |
| 内容创作 | 公众号、今日头条、百家号、大鱼号、小红书创作 |
| 知识付费 | 得到、知乎盐选、喜马拉雅、腾讯课堂 |
| 金融证券 | 同花顺、东方财富、各银行APP、各基金APP |
| 出行住宿 | 12306、携程、飞猪、去哪儿、滴滴、高德 |
| 工具订阅 | iCloud、百度网盘、WPS、Office365、各类SaaS |
| 音视频 | 爱奇艺、腾讯视频、优酷、芒果TV、网易云音乐、QQ音乐 |
| 生活服务 | 美团、饿了么、大众点评、朴朴超市 |
| 学习与考试 | 学信网、各考试报名系统 |

**输出物**：用户专属《数字资产全景报告》（PDF/可打印）

#### 模块二：数字资产分类与登记

**功能描述**：用户确认资产后，系统自动辅助分类并登记。

**自动分类逻辑**：
```
数字资产
├── 财产型（明确经济价值）
│   ├── 余额类：支付宝余额、微信零钱、银行卡余额
│   ├── 虚拟物品：游戏装备、皮肤、NFT、数字藏品
│   ├── 权益类：未到期会员、付费订阅、电子书
│   └── 商业账号：自媒体账号（有广告收入）、网店账号
│
├── 人格型（情感/隐私价值）
│   ├── 社交记录：聊天记录、朋友圈、私信内容
│   ├── 个人创作：照片、视频、博客、文档
│   └── 身份数据：浏览记录、搜索历史、位置记录
│
└── 混合型（兼具财产与人格）
    └── 如：有收入的公众号、有价值的抖音账号
```

**登记内容**：
- 账号标识（不含密码，密码由用户另行保管）
- 预估价值（选填）
- 资产类型标签
- 扣押/处理意愿

#### 模块三：处置意愿设定

**功能描述**：用户为每份数字资产选择身后处置方式。

**处置选项**：

| 处置方式 | 适用资产类型 | 说明 |
|----------|-------------|------|
| 指定继承人继承 | 财产型 | 转给特定个人 |
| 变现后分配 | 财产型 | 变卖后按比例分配 |
| 保留纪念化 | 人格型 | 如微信思念小程序、账号转为"纪念账号" |
| 授权查阅权 | 人格型 | 指定人可查看但不可登录 |
| 彻底删除 | 高隐私 | 不留痕迹 |
| 捐赠指定方 | 全部类型 | 捐给特定个人/组织 |
| 不做处理 | 全部类型 | 任由平台自行处置 |

#### 模块四：数字遗产处置方案生成引擎

**功能描述**：自动生成一份完整的数字遗产处置方案文档。

**输出物**：
1. **《我的数字遗产清单》**：结构化的数字资产清单
2. **《数字遗产处置意愿书》**：用户处置意愿汇总（非遗嘱本身，配套用）
3. **《数字遗产遗嘱条款模板》**：直接嵌入传统遗嘱的数字资产部分
4. **《继承人操作手册》**：按继承人分列的操作指南
5. **《各平台继承指引》**：每个平台的继承条件、所需材料、办理流程

#### 模块五：身后执行系统（Dead Man's Switch）

**机制设计**：

```
用户设置检查周期（如每月1日）
        │
        ▼
   到期提醒登录确认
        │
   ┌────┴────┐
   │         │
   ▼         ▼
 用户登录  用户未登录
   │         │
   │         ▼
   │    第一阶段通知（3天后）
   │    发送邮件+短信提醒
   │         │
   │    ┌────┴────┐
   │    │         │
   │    ▼         ▼
   │  用户仍    用户响应
   │  未登录     │
   │    │       结束
   │    ▼
   │  第二阶段通知（再7天后）
   │  通知紧急联系人
   │    │
   │  ┌─┴──┐
   │  │    │
   │  ▼    ▼
   │ 有人  无人确认
   │ 确认   │
   │  │    ▼
   │  安全  第三阶段（再14天）
   │        确认用户可能已离世
   │            │
   │            ▼
   │       向遗产执行人发送
   │       "密钥信封"
   │
   └────────────┘
```

**关键安全设计**：
- 三级确认链，防止误触发
- 紧急联系人可随时报告确认安全/确认离世
- 密钥信封包含加密指引，执行人凭死亡证明解锁

#### 模块六：继承人向导

**面向继承人（第二用户入口）**功能：
- 登录查看逝者预设的遗产清单与处置方案
- 继承操作"一键导航"：每个平台需要什么证件、去哪里提交、流程是什么
- 法律文书自动生成：公证书申请草稿、平台申请表等
- 进度追踪：跟踪各平台继承办理进度

## 五、技术架构

### 5.1 推荐技术栈

| 层 | 技术选型 | 理由 |
|----|----------|------|
| 前端框架 | Vue 3 + TypeScript | 适合快速开发，生态成熟 |
| 桌面壳层 | Tauri (Rust) | 安装包仅5-10MB、内嵌SQLite、跨平台、内存安全 |
| 数据库 | SQLite (本地) | 零配置、单文件、完美契合"本地优先+隐私优先" |
| 加密 | AES-256-GCM + PBKDF2 | 银行级加密，密钥仅用户持有 |
| 文档生成 | docx模板引擎 + PDF渲染 | 生成遗嘱条款、操作手册等 |
| 通知（可选） | SMTP邮件 + 第三方SMS | Dead Man's Switch的远程提醒 |
| 构建 | Vite | 开发体验好、构建快 |

**技术架构亮点**：
- **纯桌面端优先**：数据不上云，不上服务器，所有敏感数据仅存本地加密SQLite文件
- **源码本体小巧**：整个应用<15MB，一键安装
- **可扩展**：未来可扩展"云端加密备份"（用户自主决定是否开启）

### 5.2 数据隐私设计（合规核心）

原则：**我们看不到用户数据、我们也看不到用户的数字资产**

- 所有数据仅存本地SQLite，用用户自定义主密钥加密
- 无服务器、无云端同步（除非用户主动开启加密备份）
- 产品可声明：**"即便我们（开发者）也无法读取用户的数字遗产数据"**

### 5.3 项目里程碑

| 阶段 | 时间 | 交付物 |
|------|------|--------|
| 立项+数据库搭建 | 第1周 | 100+平台数据库+MVP原型 |
| MVP核心功能 | 第2-3周 | 资产发现+登记+导出 |
| 法律文书引擎 | 第4周 | 遗嘱条款模板+操作手册 |
| Dead Man's Switch | 第5周 | 三级确认链 |
| 继承人向导 | 第6周 | 继承人入口+操作导航 |
| 内容填充+打磨 | 第7周 | 各平台政策更新 |
| 测试+Demo准备 | 第8周 | 用自身数据演示+答辩材料 |

总开发周期：约8周（一个人全职投入）

## 六、商业模式（小挑参赛用）

### 6.1 价值主张

**对C端用户（民众）**：免费基础版（发现+登记+导出），99元/终身 Pro版（全套法律文书+Dead Man's Switch）

**对B端机构**：
- 中华遗嘱库导流合作：提供数字化工具支撑
- 公证处/律所：专业版授权
- 保险公司的保单受益人指定服务

**对G端政府**：老龄化社会治理数字工具，可纳入政务服务合作

### 6.2 收入流

| 来源 | 模式 | 规模预估 |
|------|------|----------|
| C端付费（个人用户） | 99-199元/年或199元/终身 | 年轻群体遗嘱意识提升 |
| B端机构授权 | 年费制（律所/公证处） | 法律服务机构刚需 |
| G端政府采购 | 项目制 | 老龄化治理工具 |
| 中华遗嘱库/遗嘱机构合作 | 技术服务费 | 数据互补 |

### 6.3 护城河

1. **数据库壁垒**：持续积累的各平台政策数据库（时新性+人力投入）
2. **法律+技术双团队**：纯技术团队做不了（不懂法），纯法律团队做不了（不会开发）
3. **用户数据网络效应**：用户越多→发现引擎越精准（本地机器学习优化）
4. **隐私信誉**：构建"最不可能泄露用户数据"的信任基础

## 七、参赛策略

### 7.1 赛道选择

**推荐赛道**：社会治理和公共服务 - 政务服务组（或消费生活组）

**理由**：
- 数字遗产本质是"公民财产传承"的治理问题
- 贴合广东省"百千万工程"中的民生服务提升
- 2026最高法新规提供法理基础

### 7.2 答辩核心卖点（评委30秒记住你）

1. **"中国每年有1000万网人死亡，每个死者平均留下10-30个无人处理的数字账号"**（数字冲击）

### 7.3 评审要点压测（预判评委问题）

| 可能的质疑 | 应对答案 |
|-----------|---------|
| "这会不会涉及用户隐私泄露法律风险？" | 所有数据本地AES-256加密存储，不上传，我们看不到用户任何数据。用户随时可以导出并永久删除我们的所有信息。 |
| "没有平台配合API，你怎么自动发现数字资产？" | 我们不声称能自动查到所有账号；而是基于用户自主申报+系统引导式发现（"您可能忘了这些平台"），最终由用户确认。核心是"提醒+组织"，不是"监控"。 |

| "市场上已经有中华遗嘱库在做这个了？" | 中华遗嘱库做线下实体遗嘱，不做资产发现引擎；我们的数字资产发现功能是纯中华遗嘱库不做的，是互补不是竞争。 |

| "怎么盈利？" | 三层收入见商业模式部分，且可与中华遗嘱库等机构做合作分润。 |
| "怎么保证政策更新？" | 在线政策库（可远程更新），一次开发持续维护。 |

### 7.4 校赛突围策略

校赛阶段核心逻辑：**"真实感+专业感+创新性"三角均衡**

3. **创新性**：全中国100+平台覆盖+发现引擎+全链路——评委一看就知道这不是随口说的
